TL;DR macOS R-devel arm64 binaries now use:
> .Platform$pkgType
[1] "macos.binary.arm64"
> contrib.url("", type="binary")
[1] "/bin/macos/arm64/contrib/4.7"
(note the lack of x at the end of macos!) and .tar.xz binaries instead of .tgz. In addition, we are experimenting with switching to the flang compiler: https://github.com/R-macos/llvm-project/releases

---

Starting with R 4.6.0 we have introduced new features for packages such as SHA256 checksums, signing and well-defined repository layout and format for binaries regardless of platform. In R 4.6.0 macOS and Windows are still using "legacy" binaries, but for R-devel (presumably 4.7.0-to-be) we want to switch to the new layout/format so we can deprecate the old format, code and use the new features.

To that end, the R-devel nightly builds are now setup to use "macos.binary.arm64" as R_PLATFORM_PKGTYPE which means the location of binaries is now "/bin/macos/arm64/contrib/4.7". The custom binaries are now defined as .tar.xz (we experimented with .tar.zstd, but unfortunately macOS tools only support xz natively and the differences are not worth the bother). This means that the repository layout is changing - there was a request to drop the x at the end of macosx since it is long disused and now leveraging R_PLATFORM_PKGTYPE allows us to finally do that.

If you have tools that assumed .tgz as macOS binaries, those will need to be adjusted to recognize .tar.xz as well (while at it, you should so that ideally in platform-independent way as this can be used for Linux, Windows and others). Officially, binaries are now defined by their Built: field and in PACKAGES metadata the location is recorded in the File: field and possible extensions are .tar.bz2, .tar.xz and .tar.zstd.

As part of the modernisation of the toolchain we are now experimenting with the flang compiler, the latest binaries are available at
https://github.com/R-macos/llvm-project/releases
but those may still be updated as needed for better compatibility.

As this point the package binaries are not synced to the CRAN master yet, so use https://mac.r-project.org as the mirror for the latest R-devel macOS package binaries.

This is mainly a heads-up for things to come, nothing is set in stone so comments are welcome.

Cheers,
Simon

fibinet <- function(fidx = 5) {
if(is.numeric(fidx)) {
        fidx <- as.character(trunc(fidx))
    }
# loop over length(fidx)
fout <- as.bigz(rep(0,length=length(fidx)))
    for(jf in 1:length(fidx)) {
        foo <- paste0('Simplify(1/k* (  ( (1 + k)/2)^', fidx[jf], '- ((1 -
k)/2)^', fidx[jf], ' ) )')
        bar <- yac_str(foo)
        foob <- gsub('[/]([0-9]{1,})','/as.bigz("\\1")',bar)
        foond <- unlist(strsplit(foob,'/'))

        foos <- unlist(strsplit(foond[1], '\\^'))
# "fix" first element as it's not in the loop
        foos[1] <- '(1'
# need to fix the final numerator element's ')'
        foos[length(foos)] <- gsub(')','',foos[length(foos)] )
        for(jp in 2:(length(foos))) {
            pxe <- regmatches(foos[jp],regexpr('^[0-9]{1,}',foos[jp]) )
            # that gets the exponent as a string
            fxe <- as.character(as.numeric(pxe)/2)
            foos[jp] <- gsub(paste0('^',pxe),paste0('^',fxe), foos[jp])
            # except that those coefficients in numerator exceed maxInt, so
have to fix them
        # one by one as well.  ewwww
            pxc <- unlist(strsplit(foos[jp],'[+]'))
            pxc[2] <- gsub('[*]k','',pxc[2])
            fxc <- paste0('*k',pxc[1], '+as.bigz("', pxc[2],'")')
            foos[jp] <- fxc
            } #end jp loop
    foof <- paste0(c(foos,')'),collapse='',sep='')
    foof <- gsub('k','5',foof)
    fout[jf] <- eval(parse(t= paste0(foof,'/',foond[2])))
    }    #end jf loop
return(invisible(list(idx=fidx,valx=fout)))
}
